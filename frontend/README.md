# MONTIRO — фронтенд

Часть монорепозитория. Бэкенд живёт в `../backend`, общие правила проекта —
в `../CLAUDE.md`.

React 18 · TypeScript · Vite · Tailwind CSS 3 · lucide-react · lenis · react-router

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build
npm run preview
```

### Админка

Адрес `/admin`. Вход по логину и паролю, токен хранится в браузере.
Товары: список, добавить, изменить, удалить. Заказы: список, открыть, сменить
статус. Шапки и подвала магазина там нет. **Кнопки удалить заказ нет
и не должно быть** — заказ отменяется статусом `canceled`.

Над списком заказов — вкладки с числом в скобках (`ORDER_TABS` в
`src/lib/admin.ts`):

| Вкладка | Статусы |
| --- | --- |
| Активные (по умолчанию) | `new`, `awaiting`, `paid`, `shipped` |
| Новые | `new` |
| Ждут оплату | `awaiting` |
| Оплачены | `paid` |
| Отправлены | `shipped` |
| Завершены | `done` |
| Отменены | `canceled` |
| Все | всё, включая неизвестные |

Фильтрация — **на фронте, по полю `status` из `GET /orders`**, новых
эндпоинтов не нужно. Счётчики пересчитываются сразу после смены
статуса. Открытая вкладка живёт в адресе (`?tab=new`), перезагрузка её
не теряет.

**Переключатели — в `src/lib/admin.ts`, по флажку на эндпоинт:**

```ts
export const ADMIN = {
  login: true,         // POST   /login
  createProduct: true, // POST   /products          (Bearer)
  updateProduct: true, // PATCH  /products/{id}     (Bearer)
  deleteProduct: true, // DELETE /products/{id}     (Bearer)
  orders: true,        // GET    /orders            (Bearer)
  orderStatus: true,   // PATCH  /orders/{id}       (Bearer)
}
```

Выключенный флажок не прячет экран — кнопка становится неактивной и подписана,
какого эндпоинта не хватает. Ставишь `true`, когда он заработал.

Поле `images` уходит **строкой через запятую**, не массивом — в базе это `str`,
и массив даёт 422 `images: Input should be a valid string`. В форме это
по-прежнему список (одна ссылка на строку), склейка — в `toWire()`
(`src/lib/admin.ts`, переключатель `IMAGES_WIRE`). Обратно чтение понимает и
строку через запятую, и JSON-строку, и массив.

Изменение товара — `PATCH /products/{id}`, и уходят **только изменённые поля**:
поправил цену — ушло `{"price": 77700}`. Сохранение без правок не шлёт запрос
вообще.

Статусы заказа — ровно шесть, ключи как в базе (`awaiting`, и `canceled` с
одной L):

| ключ | подпись |
| --- | --- |
| `new` | Новый |
| `awaiting` | Счёт выставлен |
| `paid` | Оплачен |
| `shipped` | Отправлен |
| `done` | Завершён |
| `canceled` | Отменён |

`PATCH /orders/{id}` принимает `{"status": "..."}`.

Вход — только JSON: `{"username": "...", "password": "..."}`.

### Корзина и заказ

Корзина — `src/lib/cart.tsx`, переживает перезагрузку (`localStorage`,
ключ `montiro.cart.v1`, все чтения и записи в try/catch).

**Весь переключатель отправки заказа — в `src/lib/orders.ts`:**

```ts
export const ORDERS = { enabled: true, path: '/orders', timeout: 20_000 }
```

**`false` — это рубильник, а не ошибка.** Пока он выключен, запроса нет вообще
и кнопка сразу показывает блок «Не удалось оформить заказ» с WhatsApp на выбор
покупателя. Если этот блок появляется, а в сетевой вкладке нет запроса на
`/orders` — дело в этом флаге. Автоматически вкладка не открывается никогда.

Тело запроса:

```json
{ "customer_name": "...", "phone": "...", "delivery_type": "pickup" | "delivery",
  "address": null, "comment": null, "items": [{ "product_id": 3, "quantity": 1 }],
  "idempotency_key": "..." }
```

`idempotency_key` — `crypto.randomUUID()`, создаётся один раз на попытку
оформления и **не меняется при повторной отправке** — «Попробовать
снова» шлёт тот же ключ, чтобы дошедший запрос не стал вторым заказом.

Числовые id уходят числами. На 201 корзина очищается и открывается `/order`.
Номер и телефон на экране успеха берутся **из ответа сервера** (`id`,
`phone`), а не из формы — введённый номер только как запасной вариант.
WhatsApp после оформления не открывается — внизу страницы только мелкая
строчка «Есть вопрос? Написать в WhatsApp».

**400, 404 и 422 не повторяются** — это сервер посмотрел и отказал.
Текст из `detail` показывается покупателю дословно («Корзина пуста»,
«Неверное количество», «Товар не найден», «Товара нет в наличии») —
заголовок «Заказ не принят» и кнопка «Открыть корзину», **без WhatsApp**:
распроданные часы правятся в корзине, а не в мессенджере.

Всё остальное (таймаут, 5xx) считается «сервер не ответил»: блок «Не
удалось оформить заказ» с кнопкой в WhatsApp и готовым текстом. Корзина
остаётся в обоих случаях, кнопку нажимает покупатель.

### Фильтры каталога

Всё состояние фильтров лежит в адресе — отфильтрованную выдачу можно скинуть
покупателю ссылкой: `/catalog?b=Rolex&min=50000&sort=price-asc`.

| Параметр | Что значит                                                      |
| -------- | --------------------------------------------------------------- |
| `q`      | поиск по названию и бренду                                       |
| `c`      | категория                                                        |
| `b`      | бренд                                                            |
| `min`    | цена от                                                          |
| `max`    | цена до                                                          |
| `sort`   | `price-asc`, `price-desc`, `name`; по умолчанию сначала в наличии |

Категории, бренды и границы цены **не захардкожены** — собираются из того, что
вернул API. Добавишь новый бренд в админке — чип появится сам. Неизвестное
значение в адресе показывает всё, а не пустую страницу. Параметр исчезает из
адреса, когда возвращается к значению по умолчанию.

### Важно при деплое

Роутер — `BrowserRouter`, то есть адреса `/catalog` и `/product/5` должны
отдавать тот же `index.html`. Иначе прямая ссылка даст 404.

- Netlify / Cloudflare Pages — уже настроено файлом `public/_redirects`.
- Vercel — добавь rewrite `/(.*)` → `/index.html`.
- `vite preview` — флаг `--single`.
- nginx — `try_files $uri /index.html;`
- Если фронт раздаёт FastAPI, то любой неизвестный путь должен вернуть
  `index.html` (статика по префиксу `/assets`, а всё прочее — на индекс).

## Подключение к API

Весь обмен с бэкендом — в **одном** файле, `src/lib/api.ts`. Больше нигде
`fetch` нет.

```ts
const API_BASE = VITE_API_BASE ?? (DEV ? '/api' : 'https://montiro.onrender.com')
```

**В разработке настраивать нечего.** `npm run dev` поднимает прокси: всё, что
начинается с `/api`, уходит на `http://127.0.0.1:8000` (см. `vite.config.ts`).
Браузер при этом общается только со своим origin — **CORS не участвует вообще**,
на локальном FastAPI ничего настраивать не нужно.

Достаточно, чтобы бэкенд слушал `127.0.0.1:8000`. Другой порт — заведи
`frontend/.env.local` (образец в `.env.example`):

```bash
VITE_API_TARGET=http://127.0.0.1:9000
```

В собранной версии (`npm run build`) прокси нет — там адрес зашивается в бандл,
по умолчанию `https://montiro.onrender.com`, и вот **на проде CORS уже нужен**:
домен сайта в `allow_origins` FastAPI.

Перебить адрес целиком (например, ходить из dev прямо на прод) можно через
`VITE_API_BASE` — но тогда CORS понадобится и в разработке. `.env.local`
не коммитится; после правки любого из этих файлов перезапусти `npm run dev`.

### Что фронт ждёт от `GET /products` и `GET /products/{id}`

Поля читаются мягко, ломаться на них не надо:

- `price`, `old_price` — число или строка (`"39 900"` тоже разберётся).
  `old_price` показывается зачёркнутым **только если он больше `price`**;
  пустой, `0` или меньший — просто не показывается. Процентов скидки нет
  нигде и быть не должно.
- `in_stock` — `true/false`, `"true"`, `1`. Пусто = «под заказ».
- `image` — главная картинка, абсолютный URL.
- `images` — массив, или JSON-строка массива, или список через запятую, или
  пусто. Склеивается с `image` и дедуплицируется.
- `category` — строка. Из неё строятся фильтры каталога.
- `mechanism`, `case_material`, `strap_material` — строки; пустые строки
  в характеристики не попадают.
- Битая ссылка на картинку подменяется на `src/assets/watch-still.jpg`.
- `GET /products/{id}` на несуществующем id должен отдавать **404** — фронт
  по нему показывает «Такой модели нет», а не «сервер не отвечает».
- Нужен CORS: домен сайта в `allow_origins`.

### Холодный старт Render

Три попытки с таймаутами 12 / 25 / 45 секунд (`ATTEMPT_TIMEOUTS` в `api.ts`).
Пока идёт загрузка: каталог показывает скелетоны, товар — скелетон,
`Featured` на главной — заглушку `PLACEHOLDER`. Пустого экрана не бывает
ни в одном состоянии. Если не ответил совсем — карточка с кнопкой
«Попробовать снова» и ссылкой на WhatsApp. 404 не ретраится.

## Палитра

Почти чёрная, но освещённая как предметная съёмка. Все токены — в `:root`
в `src/index.css` и в `tailwind.config.js`. Золото `#C9A86A` — единственный
тёплый цвет: секундная стрелка, тонкие линейки, ховеры.

## Часы на главной

Первый экран — реальное видео (`src/assets/watch-loop.mp4`, 347 КБ): чёрный
корпус, белый циферблат. Зациклено бесшовно, звука нет, на
`prefers-reduced-motion` подменяется постером.

Чёрный фон видео растворяется в странице эллиптической маской `EDGE_MASK`
в `Hero.tsx`. Радиус маски должен быть не больше 50% — иначе затухание не
успевает завершиться и появляется видимый прямоугольник.

Единственное движение на первом экране — скролл: камера наезжает на циферблат,
из его центра растёт белый круг и заливает экран. Секция `Featured` покрашена
тем же белым (`DIAL_WHITE` экспортируется из `Hero.tsx` — в двух местах цвет
должен совпадать до символа, иначе на стыке видно шов). Часы **не прыгают** —
ни сальто, ни отскока.

## Оплата

Онлайн-оплаты нет. Заказ уходит через `POST /orders`, счёт выставляется
в Kaspi на номер покупателя в течение часа.

## CSS

Современный, не «как в 2018-м». Отдельный слой в конце `src/index.css`.

| Что | Где | Что заменило |
| --- | --- | --- |
| `oklch()` палитра | `:root` | hex, по которому не понять, что светлее |
| `color-mix(in oklab)` | акценты, обводка фокуса | rgba, подобранные на глаз |
| `:has()` | панель фильтров, карточка | состояние в React ради стиля родителя |
| `:focus-within` | поле поиска | обработчик focus/blur |
| `:focus-visible` | обводка фокуса | `:focus`, срабатывавший и на мышь |
| контейнерные запросы, `cqw` | карточка товара | брейкпоинты вьюпорта внутри сетки |
| `aspect-ratio` | плашка карточки | фиксированные высоты на каждый брейкпоинт |
| `clamp()` | `.t-display` | лесенка `text-4xl sm:text-5xl md:text-6xl` |
| `text-wrap: balance` / `pretty` | заголовки, абзацы | ручные переносы |
| `line-clamp` | длинные названия | обрезка в JS |
| `tabular-nums` | все цены (`.figure`) | цифры разной ширины, цены не в колонку |
| `@property` | свет на плашке карточки | градиент, который прыгал вместо движения |
| `animation-timeline: view()` | появление карточек | IntersectionObserver |
| `linear()` | выпадающий список | `cubic-bezier`, который так не умеет |
| `mix-blend-mode` | огромная надпись в подвале | плоский серый |
| `dvh` | первый экран | `vh`, который ломает адресная строка телефона |

Всё новое прикрыто `@supports` — это магазин, кто-то откроет со старого
телефона.

**Не используется намеренно:** нативный `@layer` (Tailwind 3 отдаёт утилиты
без слоёв, а не слоёный CSS всегда сильнее слоёного — наши переопределения
молча перестали бы работать), `@scope` и `color-contrast()` — ещё не во всех
браузерах.
